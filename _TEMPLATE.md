# How to use this template

The block of tags above this section has to stay exactly where it is, on the
very first line of the file. It only works from there. If anything gets pushed
above it, GitHub stops treating it as tags and displays it as a jumble of
text instead.

| Step | What you do |
|---|---|
| 1 | Copy this whole file |
| 2 | Save it as `projects/your-page-name.md` |
| 3 | Replace everything written in CAPITALS with your own content |
| 4 | Delete this instructions section, down to and including the line of dashes |

Everything in CAPITALS is a placeholder rather than an example. None of it is
a value you should keep.

## Where to find the value for each tag

| Tag | What to put in it | Where the allowed values are |
|---|---|---|
| `title` | The name of your page | Write it yourself |
| `goal` | One short line in your own words | Write it yourself |
| `tools` | Every tool your page needs | Table in [TAGS.md](TAGS.md) |
| `sensitivity` | What is safe to put into the tool | Table in [TAGS.md](TAGS.md), after checking [CLEARANCE.md](CLEARANCE.md) |
| `status` | Whether it works yet | Table in [TAGS.md](TAGS.md) |
| `job` | Who it is for. Optional | Table in [TAGS.md](TAGS.md), or delete the line |
| `effort` | How long it takes. Optional | Table in [TAGS.md](TAGS.md), or delete the line |
| `tokens` | What it costs to run. Optional | Table in [TAGS.md](TAGS.md), or delete the line |

Keep the square brackets on the five tag lines that have them. They are what
make GitHub display your values as tags rather than as plain text.

If the tag you need does not exist in [TAGS.md](TAGS.md) yet, use it anyway
and then add it to that page in the same commit. Inventing a tag is allowed.
Keeping it to yourself is not.

## If you want to see a finished page first

Open any file in [`projects/`](projects/) whose name starts with `EXAMPLE-`.
Those are filled in properly and show you what a real page looks like.

## If writing it out feels slow

Paste your rough notes, or even a transcript of you using the tool, into an
LLM along with this template, and ask it to draft the page. Then read what it
produced and correct whatever it guessed wrong.

The one thing not to delegate is the sensitivity tag. Set that one yourself.

## Adapt, don't clone

This is the most useful section on the page, so please do not leave it empty.

Explain which parts of what you have described are specific to your own
situation. That might be your file structure, the name of your project, the
particular document you were working with, or the way your team phrases
things. Whoever reads this will need to swap those parts out.

Also mention anywhere the results will not come out the same twice. The same
prompt on a different day can produce something quite different, so it helps
to say where you have seen that happen.

If there is anything worth knowing about how many tokens this uses, or any
rate limit you ran into, this is a good place to mention it.
